# DRAVEX real-device quality verification

## Scope

Use this checklist after the temporal-sampling change. Automated CI can prove the app builds, browser flows work, and exported files pass technical checks; it cannot establish whether a real edit selects the best human-perceived moments or whether a particular Android device decodes 4K smoothly.

## A. Action-moment selection

Use the same rights-cleared 20–30 second drift clip for all runs. Keep the output duration, aspect ratio, music, and style settings unchanged.

1. Run automatic montage twice to identify whether the result is deterministic or changes materially between runs.
2. Note the source timestamps for drift initiation, apex, smoke/peak motion, and exit.
3. For each of the four variants, record which of those moments are included, whether a selected cut repeats source footage, and whether a cut begins/ends mid-action.
4. Compare 1080p and 4K output only after the selected timestamps are recorded, so rendering quality does not confound selection quality.

Score each variant from 0–2 for moment relevance, temporal continuity, variant distinction, transitions, framing, and technical export. Do not claim semantic action recognition from motion scores alone.

## B. Transition review

Inspect each join at normal speed and frame-by-frame where possible. Record the source time before and after each join. Flag black frames, frozen frames, abrupt scale/crop changes, repeated footage, transition overlap that hides the action, or a transition that lasts longer than the useful action. Attach the exported file and browser QA artifacts to the test report when possible.

## C. Separate 4K playback from 4K export

First establish which path lags:

- **Editor source preview:** play the original 4K source without generating an edit.
- **Rendered variant preview:** compare the short, low-resolution preview generated by DRAVEX.
- **Exported 4K file:** play the saved file in a separate Android player, then compare the same file in the browser.
- **Exported 1080p file:** use the same source, duration, style, and audio as the 4K export.

Record device/browser, source codec and frame rate if known, source dimensions, export dimensions, file size, whether audio is enabled, and where the lag occurs. If only 4K playback lags in both browser and an external player, device decoding/load is a likely contributor. If only the DRAVEX editor preview lags, inspect its decode/render loop. If the exported file itself freezes or drops frames across players, inspect the render pipeline and bitrate/codec. These are diagnostic hypotheses, not conclusions before testing.

## D. Acceptance gates

- Build and Playwright browser QA pass on the exact tested commit.
- No empty or unplayable export; output dimensions match the selected profile.
- No out-of-range trims or unintended repeated source intervals.
- Four variants differ in selected timestamps or pacing, not only color/effect settings.
- Real-footage review is recorded separately from synthetic-fixture CI.
- Do not merge into `main` until the user reviews real-footage results and required checks are green.
